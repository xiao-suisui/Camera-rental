# Camera Rental 项目优化完善计划书（2026-03-14）

> 适用仓库：`Camera-rental`  
> 覆盖范围：`gateway`、`user-service`、`device-service`、`order-service`、`coupon-service`、`common`、`frontend`、`nacos_config`  
> 目标：在不引入 Seata、暂不引入 MapStruct 的约束下，4-6 周内完成“可开源、可生产、可扩展（RabbitMQ/ES）”的优化闭环。

---

## 1. 现状评估

### 1.1 已完成

- 安全基线已具备：`@AdminOnly` 与 `AdminInterceptor` 已落地。
- 配置脱敏治理已执行：`cipher-config.yaml` 已从 Git 排除，模板文件保留。
- `order-service` 已移除 Seata 相关集成，当前不依赖分布式事务。
- 订单与优惠券部分性能点已落地（如分页、批量更新、原子计数）。
- 网关文档聚合可用：`doc.html` 可访问；Druid 基础监控可访问。

### 1.2 进行中

- 业务状态机语义仍需进一步统一：
  - 目标流程是“支付 -> 出租者发货 -> 租用者使用 -> 归还”。
  - 前后端状态常量和展示文案仍有收敛空间。
- 日志目前以控制台/文件为主，尚未形成完整“持久化 + 检索 + 审计”闭环。
- 生产配置规范仍需强化（命名空间隔离、生产日志级别、监控访问控制等）。

### 1.3 待开始

- RabbitMQ 接入仍处于计划阶段（尚未形成稳定生产链路）。
- Elasticsearch 接入尚未落地（搜索与日志检索能力待升级）。
- 开源门禁流程需补齐（敏感信息扫描、依赖合规、发布清单）。

## 2. 问题分级

### 2.1 P0（阻断上线 / 高风险）

1. 订单主流程状态机需完全映射业务链路，避免前后端语义偏差。
2. 日志持久化能力不足，故障追踪与审计查询成本高。
3. MinIO 长期公开访问缺少补偿安全策略（防盗链、上传约束、生命周期治理）。
4. 生产配置存在误配风险（命名空间、日志、文档与监控暴露面）。
5. 配置秘密虽已治理，但缺少持续化门禁（提交前与 CI 阻断）。

### 2.2 P1（影响稳定性 / 可维护性）

1. 订单通知链路仍有同步耦合，缺少异步削峰与可靠投递闭环。
2. 部分接口模型与实体耦合较深，长期演进成本高。
3. 可观测性体系未统一量化（SLO、关键指标、告警阈值）。
4. 开源发布元信息需进一步标准化（版本、变更记录、兼容说明）。

### 2.3 P2（体验与扩展优化）

1. 前端状态展示、错误提示与后端错误码映射仍可增强一致性。
2. 搜索与审计仍偏数据库直查，缺少 ES 级检索能力。
3. 网关限流、重试、请求体大小控制可继续细化。

## 3. 4-6 周执行路线图（建议 6 周稳态）

### 第 1 周：P0 基线收敛

- 冻结统一订单状态字典（后端枚举、前端常量、文档统一）。
- 输出 MinIO 长期公开访问补偿安全方案（策略 + 检查项）。
- 明确日志持久化一期目标（先可落盘和可追溯）。
- 建立配置秘密门禁方案（本地扫描 + CI 阻断）。

### 第 2 周：P0 落地实施

- 完成日志卷挂载、滚动归档与服务重启不丢日志。
- 推进 `@OperationLog` 持久化（优先入库，后续可异步入 ES）。
- 完成生产配置核对与基线固化（Nacos、CORS、监控访问策略）。
- 发布“生产最小安全基线 v1”。

### 第 3 周：P1 稳定性（RabbitMQ 最小链路）

- 按既有计划接入 RabbitMQ 基础设施与共享配置。
- 将订单关键通知链路改为事件投递（覆盖支付/发货/归还关键环节）。
- 落地消费者幂等、重试与死信（DLQ）机制。
- 保留同步链路开关用于灰度和回滚。

### 第 4 周：P1 可维护性

- 推进 VO/DTO 分层（手动映射，保持当前不引入 MapStruct 的策略）。
- 建立核心业务指标看板（订单流转、消息投递、日志持久化）。
- 补齐开源发布标准文档（版本策略、兼容性、风险说明）。

### 第 5 周：P2 扩展位（ES 接入）

- 定义 `device_index` 与 `operation_log_index` 索引结构。
- 打通全量初始化 + 增量同步（基于 MQ 事件）。
- 搜索接口支持“ES 优先 + MySQL 回退”策略。
- 增加一致性对账任务与回放流程。

### 第 6 周：联调与准发布

- 端到端验证：支付 -> 发货 -> 使用 -> 归还全链路可追溯。
- 执行开源发布前与生产部署前双清单签核。
- 输出上线与回滚 Runbook v1.0。

## 5. 风险与回滚策略

| 风险 | 触发表现 | 预防策略 | 回滚策略 |
|---|---|---|---|
| 状态机调整引发兼容问题 | 前端显示异常、流转失败 | 增加兼容映射层并灰度发布 | 回切旧映射，保留双读窗口 |
| MQ 引入引发重复/堆积 | 消息重复或消费延迟 | 幂等键、重试上限、DLQ、监控告警 | 关闭 MQ 消费开关，临时恢复同步通知 |
| 日志持久化带来性能抖动 | 接口 RT 升高 | 异步写入、批量落库、采样策略 | 降级为文件日志，暂停入库链路 |
| MinIO 公开访问被滥用 | 外链盗刷、违规文件 | 防盗链、签名控制、生命周期策略 | 临时切换私有桶 + 预签名访问 |
| 生产配置误发布 | 服务不可用或安全暴露 | 命名空间隔离、变更审批、配置 diff | 回滚到上一配置版本 |

## 8. RabbitMQ / ES 后续扩展位

### 8.1 RabbitMQ 事件模型

- 统一事件：`OrderPaid`、`OrderShipped`、`OrderInUse`、`OrderReturnApplied`、`OrderReturnedConfirmed`。
- 第一阶段以 `order-service` 生产、`user-service` 消费为主（站内通知）。
- 保持“无 Seata”约束，采用本地事务 + 可靠投递 + 补偿机制。
- 设置同步链路兜底开关，避免一次性强切换风险。

### 8.2 Elasticsearch 扩展

- `device_index` 用于设备搜索；`operation_log_index` 用于审计检索。
- 采用“全量导入 + MQ 增量更新 + 回放补偿”机制。
- ES 故障时自动回退 MySQL，保证核心下单流程不受阻断。

### 8.3 MinIO 长期公开访问补偿策略（强制）

- 公开读、私有写分离，禁止匿名上传。
- 对象名随机化，最小化暴露原始文件信息。
- 限制 MIME 与大小，拦截可执行/高风险文件。
- 开启访问审计与生命周期策略，定期清理无效资源。
