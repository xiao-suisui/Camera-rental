## 5. 下一步执行计划（按优先级）

### P0（本周优先）

1. 订单与评价查询权限收口
- 目标：所有查询接口仅信任 `X-User-Id/X-User-Role`，不再信任 query 中的 userId。
- 范围：order-service 的列表/详情/评价查询与可评价判断链路。
- 验收：普通用户无法跨账号读取任何订单/评价数据。

2. MinIO 策略最终定稿并落地
- 目标：明确“永久公开”或“默认私有+短签”的唯一策略，并与文档一致。
- 范围：`MinioService`、上传回写链路、前端展示链路、运维配置指南。
- 验收：策略、代码、文档三者一致；旧数据可平滑读取。

3. 配置与密钥门禁
- 目标：提交前与 CI 阶段阻断明文密钥进入主分支。
- 范围：`.gitignore`、仓库扫描脚本、CI 规则。
- 验收：主分支明文密钥 0。

4. Nacos 重导入与 RabbitMQ vhost 收口（新增）
- 目标：删除远程历史配置并按仓库 `nacos_config` 全量重导，确保服务使用 `/camera-rental` 而非默认 `/`。
- 范围：`nacos_config/DEFAULT_GROUP/*`、`nacos_config/SHARED_GROUP/*`、`nacos_config/.metadata.yml`。
- 执行：先导入 SHARED_GROUP（含 `secret-config.yaml`、`rabbitmq-config.yaml`），再导入 DEFAULT_GROUP；重启 user/device/order/coupon。
- 验收：`service/scripts/check-mq-topology.ps1 -VirtualHost /camera-rental` 全量 PASS，`-VirtualHost /` 不再作为运行目标。

### P1（下周推进）

4. MQ Topology 单一来源治理
- 目标：减少多服务重复声明，避免交换机/队列配置漂移。
- 验收：拓扑声明收敛到单一来源，服务仅做按需绑定与消费。

5. Feign Fallback 收口
- 目标：补齐仍缺失的 `CouponFeignClient` 等 fallback 实现。
- 验收：依赖服务不可用时返回可控降级结果，不影响主链路稳定性。

6. 环境启动自检脚本
- 目标：提供一键检查 MySQL/Redis/Nacos/RabbitMQ 可用性的脚本。
- 验收：开发与测试环境可在启动前快速发现依赖问题。

### P2（滚动治理）

7. VO/DTO 分层改造
- 目标：controller 不直接暴露实体，降低敏感字段泄露风险。

8. ES 扩展位与回退策略
- 目标：支持 ES 优先检索，故障自动回退 MySQL。

## 7. 风险与策略（更新）

| 风险 | 触发表现 | 预防策略 | 处置策略 |
|---|---|---|---|
| MQ 重复或堆积 | 延迟升高/DLQ 增长 | 幂等键、重试上限、DLQ 监控 | 优先处理 DLQ，必要时暂停有问题消费者 |
| Outbox 堆积 | NEW/FAILED 持续增长 | 发布任务健康检查与告警阈值 | 扩容发布任务并排查 broker/network |
| 文档漂移 | 新成员误判状态 | 单一主文档 + 索引治理 | 每周同步文档与代码状态 |

## 10. 需你确认的决策（存在分歧）

1. MinIO 链接策略：是否坚持“永久公开链接”目标？
- 当前代码是 7 天预签名链接；若切换永久公开，需要同时落地防盗链、MIME 白名单与生命周期策略。

2. 操作日志二期范围：是否纳入导出与告警？
- 一期（入库+管理端筛选查询）已完成，二期可补 CSV 导出与 ERROR 告警联动。

3. 查询接口安全收口范围：是否按“严格同账号可见”推进？
- 包括订单详情/列表与评价相关查询，统一以请求头 userId 为准，不再信任 query 参数里的 userId。

4. VO 分层是否本轮推进？
- 会影响前后端契约，需要同步改前端字段消费，建议先覆盖 user/device/order 三条主链路。
