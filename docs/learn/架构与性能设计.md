# 架构与性能设计

> 本文档描述微服务拆分策略、消息通信、缓存设计、性能优化措施和未来扩展规划。

---

## 1. 微服务拆分策略

### 1.1 拆分原则

按**业务域**拆分，每个服务有明确的职责边界：

| 服务 | 职责域 | 数据表 |
|------|--------|--------|
| user-service | 用户身份、认证、消息、聊天 | user, message, chat_conversation, chat_message |
| device-service | 设备生命周期、搜索、收藏、图片 | device, device_favorite |
| order-service | 订单全流程、评价、纠纷、MQ 发件箱 | order, evaluation, dispute, mq_outbox |
| coupon-service | 优惠券发行与核销 | coupon, user_coupon |

> `mq_consume_log` 和 `operation_log` 表由各服务共用，按需写入。

### 1.2 服务间通信

项目采用 **Feign 同步 + RabbitMQ 异步** 双模式通信：

#### 同步调用（OpenFeign）

用于需要即时响应的请求-响应场景：

| 调用方 | 目标 | 用途 |
|--------|------|------|
| order-service | device-service | 创建订单时查询设备信息、锁定库存 |
| order-service | coupon-service | 创建订单时查询优惠券、核销优惠券 |
| device-service | order-service | 删除设备前检查是否存在活跃订单 |
| order-service | user-service | 纠纷模块发送站内信通知（MessageFeignClient） |

所有 Feign Client 均配置 Fallback 降级类，下游服务不可用时返回友好错误而非级联失败。order-service 的 Feign 超时配置：连接 3s，读取 10s。

#### 异步通信（RabbitMQ）

用于事件驱动的 fire-and-forget 场景，通过 Outbox 模式保证消息可靠投递。

**MQ 拓扑：**

- Topic Exchange：`camera.rental.order.topic.v1`
- Dead-letter Exchange（Direct）：`camera.rental.order.dlx.v1`
- 3 个主队列 + 3 个死信队列：

| 队列 | 消费者 | 路由键 | 用途 |
|------|--------|--------|------|
| `user.notify.q` | user-service | `order.*.notify.user` | 订单状态变更通知（发货、收货、退租申请、退租确认） |
| `device.sync.q` | device-service | `order.cancelled.release.stock` | 订单取消时释放设备库存 |
| `coupon.sync.q` | coupon-service | `order.cancelled.rollback.coupon` | 订单取消时回退优惠券 |

**Outbox 模式实现（order-service）：**

```
业务逻辑 → 同一事务写入 mq_outbox 表
         → OutboxPublishJob 每 5s 轮询（最多 100 条）
         → rabbitTemplate.convertAndSend() 发布到 Topic Exchange
         → 成功：status=SENT；失败：指数退避重试（5s×2^n，上限 300s，最多 10 次）
```

- 状态机：`NEW → SENT / FAILED`
- Publisher Confirm（correlated）+ Publisher Returns 已开启
- 每日 4:00 AM 清理 30 天前的 SENT 记录
- OutboxMetricsService 暴露 pending/failed/retry 统计

**消费者幂等保证：**

每个消费者在处理前向 `mq_consume_log` 表插入记录（唯一键 `event_id + consumer`），`DuplicateKeyException` 时 ACK 跳过。手动 ACK，prefetch=20，失败消息经 3 次重试后进入 DLQ。每日 3:30 AM 清理 180 天前的消费日志。

**拓扑检查脚本：** `service/scripts/check-mq-topology.ps1` 通过 RabbitMQ Management API 验证所有 Exchange、Queue、Binding 是否正确配置。

### 1.3 公共模块设计

`camera-rental-common` 模块包含所有服务共用的：

- 统一响应 `Result<T>` 和错误码 `ErrorCode`
- 全局异常处理器 `GlobalExceptionHandler`
- AOP 切面（操作日志、防重提交）
- 自定义注解（`@AdminOnly`、`@OperationLog`、`@RepeatSubmit`）
- 基础配置类（Redis、MinIO、MyBatis-Plus、OpenAPI）
- 管理员拦截器

> Gateway 基于 WebFlux，不兼容 Servlet 栈。在 Gateway 的 pom.xml 中通过 `<exclusion>` 排除 spring-boot-starter-web、druid、mybatis 等 Servlet 依赖。Common 模块中的 Servlet 相关 Bean 使用 `@ConditionalOnClass(HttpServletRequest.class)` 防止在 Gateway 中加载。

## 2. 缓存设计

### 2.1 多级 TTL 策略

使用 Spring Cache + Redis，按业务域定制不同 TTL：

| 缓存域 | TTL | 用途 |
|--------|-----|------|
| `device` | 30 分钟 | 设备详情 |
| `deviceSearch` | 10 分钟 | 搜索结果 |
| `user` | 1 小时 | 用户信息 |
| `coupon` | 15 分钟 | 优惠券信息 |
| `unreadCount` | 5 分钟 | 未读消息数 |

配置位置：`RedisConfig.java` 中通过 `RedisCacheManager` 的 `withInitialCacheConfigurations()` 设置。

### 2.2 缓存一致性

- **设备更新/删除/上下架** → `@CacheEvict(value = "device", key = "#deviceId")`
- **优惠券领取** → `@CacheEvict(value = "coupon", key = "#request.couponId")`
- 采用 Cache-Aside 模式：先更新数据库，再清除缓存

### 2.3 Redis 序列化

客户端：Lettuce（非 Jedis），连接池 max-active=8。

- Key：`StringRedisSerializer`（可读的字符串 Key）
- Value：`GenericJackson2JsonRedisSerializer`（JSON 格式，含 JavaTimeModule 支持时间类型）
- 缓存 Key 前缀：`camera-rental:{cacheName}:`
- 禁止缓存 null 值

### 2.4 防重提交

`@RepeatSubmit` 注解 + `RepeatSubmitAspect` 切面：

```
1. 从请求中提取 URI + 参数 + Token 生成唯一 Key
2. Redis SETNX（key, "1", interval秒）
3. 设置成功 → 放行
4. 设置失败 → 拒绝（429 Too Many Requests）
```

## 3. 网关设计

### 3.1 路由优先级

Gateway 路由按 `order` 值分级，数值越小优先级越高：

| 优先级 | Order | 路由类型 |
|--------|-------|---------|
| 最高 | 1 | Druid 监控面板路由 |
| 中 | 10 | OpenAPI 文档路由 |
| 低 | 100 | 业务路由 |

防止业务路由（如 `/user/**`）抢占 Druid/OpenAPI 子路径的请求。

### 3.2 JWT 鉴权流程

```
请求 → JwtAuthFilter (order=-100)
  → 若为浏览器 CORS 预检 OPTIONS：放行
  → 若命中管理面路径（文档/Druid/actuator info&metrics/admin）
    → 校验内网/IP 白名单，通过则放行，否则 403
  → 检查公开接口（register/login/refresh-token/device search/device detail/health）
    → 匹配则放行
  → 提取 Authorization 头
    → 无 Token 或格式错误 → 401 响应
  → 解析 JWT
    → 已过期 → code=2005,message=TOKEN_EXPIRED
    → 非法/篡改 → 401 响应
  → 将 userId 和 role 写入请求头
    → X-User-Id: {userId}
    → X-User-Role: {role}
    → X-Gateway-Request: true
    → X-Client-IP: {clientIp}
  → 放行到下游服务
```

### 3.3 Sentinel 网关流控

```yaml
spring.cloud.sentinel.scg.fallback:
  mode: response
  response-body: '{"code":503,"message":"服务繁忙，请稍后再试"}'
```

所有 5 个服务均接入 Sentinel Dashboard（`localhost:8858`），order-service 额外开启 `feign.sentinel.enabled: true`。

> **当前状态**：仅配置了 Dashboard 连接，未在代码中定义 `FlowRule`/`@SentinelResource` 等流控规则。限流规则需通过 Sentinel Dashboard 在运行时手动配置。

### 3.4 CORS 配置

```yaml
globalcors:
  cors-configurations:
    '[/**]':
      allowed-origins: ["http://localhost:3000"]
      allowed-methods: "*"
      allowed-headers: "*"
      allow-credentials: true
      max-age: 3600
```

## 4. 数据库设计优化

### 4.1 表结构总览

共 14 张表，按业务域分布：

| 表 | 所属服务 | 说明 |
|----|----------|------|
| user | user-service | 用户信息 |
| message | user-service | 站内信 |
| chat_conversation | user-service | 聊天会话（用户间唯一） |
| chat_message | user-service | 聊天消息 |
| device | device-service | 设备/相机 |
| device_favorite | device-service | 设备收藏 |
| order | order-service | 订单 |
| evaluation | order-service | 评价 |
| dispute | order-service | 纠纷（SUBMITTED → PROCESSING → RESOLVED/REJECTED） |
| mq_outbox | order-service | MQ 发件箱（Outbox 模式） |
| coupon | coupon-service | 优惠券 |
| user_coupon | coupon-service | 用户优惠券关联 |
| mq_consume_log | 各服务共用 | MQ 消费日志（幂等保证） |
| operation_log | 各服务共用 | 操作日志（AOP 切面写入） |

### 4.2 索引策略

**唯一索引（业务唯一性保证）：**

| 表 | 索引 | 说明 |
|----|------|------|
| user | uk_user_phone | 手机号唯一 |
| order | uk_order_no | 订单号唯一 |
| mq_outbox | uk_mq_outbox_event_id | 事件 ID 唯一（防重复投递） |
| mq_consume_log | uk_mq_consume_log_event_consumer | 事件+消费者唯一（幂等消费） |
| user_coupon | uk_user_coupon | 用户+优惠券唯一（防重复领取） |
| device_favorite | uk_user_device | 用户+设备唯一 |
| chat_conversation | uk_conversation_users | 用户间会话唯一 |

**普通/复合索引（查询优化）：**

| 表 | 索引 | 类型 | 说明 |
|----|------|------|------|
| device | idx_device_user | NORMAL | 按用户查我的设备 |
| device | idx_device_search | COMPOSITE | (deleted, audit_status, status) 设备列表筛选 |
| order | idx_order_user | NORMAL | 按用户查订单 |
| order | idx_order_status_created | COMPOSITE | (status, created_at) 超时取消查询 |
| user_coupon | idx_user_coupon_expire | COMPOSITE | (use_status, expire_time) 过期清理 |
| chat_message | idx_msg_conversation | COMPOSITE | (conversation_id, created_at) 会话消息时间线 |
| chat_message | idx_msg_receiver | COMPOSITE | (receiver_id, is_read) 未读消息查询 |
| mq_outbox | idx_mq_outbox_status_retry | COMPOSITE | (status, next_retry_at) 重试轮询 |
| mq_outbox | idx_mq_outbox_created | NORMAL | 按时间查询 |
| mq_consume_log | idx_mq_consume_log_consumed_at | NORMAL | 按时间清理过期记录 |
| dispute | idx_dispute_order | NORMAL | 按订单查纠纷 |
| dispute | idx_dispute_initiator | NORMAL | 按发起人查纠纷 |
| dispute | idx_dispute_status | NORMAL | 按状态筛选 |
| operation_log | idx_operation_log_type | NORMAL | 按类型筛选 |
| operation_log | idx_operation_log_user | NORMAL | 按用户筛选 |
| operation_log | idx_operation_log_created | NORMAL | 按时间查询 |

### 4.3 Druid 连接池

```yaml
druid:
  initial-size: 5
  min-idle: 5
  max-active: 20
  max-wait: 60000
  filters: stat,wall          # SQL 统计 + SQL 防火墙
  connection-properties:
    druid.stat.mergeSql: true  # SQL 合并统计
    druid.stat.slowSqlMillis: 5000  # 慢 SQL 阈值 5s
```

- `stat`：SQL 执行统计，用于 Druid 监控面板
- `wall`：SQL 防火墙，防止 SQL 注入

### 4.4 逻辑删除

设备表使用逻辑删除：`deleted` 字段（0=正常，1=已删除）。

MyBatis-Plus 全局配置：

```yaml
mybatis-plus.global-config.db-config:
  logic-delete-field: deleted
  logic-delete-value: 1
  logic-not-delete-value: 0
```

## 5. 超时与容错

### 5.1 Gateway 超时

```yaml
spring.cloud.gateway:
  httpclient:
    connect-timeout: 3000   # 连接超时 3s
    response-timeout: 10s   # 响应超时 10s
```

### 5.2 Feign 超时

```yaml
feign.client.config.default:
  connect-timeout: 5000   # 连接超时 5s
  read-timeout: 10000     # 读取超时 10s
```

### 5.3 Feign 降级

所有 Feign Client 配置 `fallback` 类，配合 Sentinel 的 `feign.sentinel.enabled: true` 触发：

| Feign Client | Fallback | 降级策略 |
|-------------|----------|---------|
| DeviceFeignClient | DeviceFeignClientFallback | 返回错误信息 "设备服务暂不可用" |
| CouponFeignClient | CouponFeignClientFallback | 返回错误信息 "优惠券服务暂不可用" |
| OrderFeignClient | OrderFeignClientFallback | 返回错误信息，阻止设备删除 |
| MessageFeignClient | MessageFeignClientFallback | 静默失败，日志记录 |

## 6. 前端性能优化

### 6.1 Vite 代码分割

```javascript
manualChunks: {
  'element-plus': ['element-plus', '@element-plus/icons-vue'],
  'vue-vendor': ['vue', 'vue-router', 'pinia'],
  'utils': ['axios', 'dayjs']
}
```

首屏只加载路由匹配的代码块 + vue-vendor 核心包。

### 6.2 路由懒加载

所有页面组件使用 `() => import(...)` 动态导入，按需加载。

### 6.3 响应压缩

Gateway 开启 HTTP 响应压缩：

```yaml
spring.cloud.gateway.httpserver.compression.enabled: true
```
