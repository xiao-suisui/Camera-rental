# 毕业设计答辩PPT大纲

## 基于Spring Cloud的相机租赁平台设计与实现

---

## 一、选题介绍（1-2页）

- **选题背景**：共享经济兴起，摄影器材单价高、使用频次低，租赁需求旺盛；现有平台存在信息不对称、流程不规范等问题
- **选题意义**：构建一个完整的B2C相机租赁平台，涵盖设备发布、在线下单、租后评价、争议处理全流程，探索微服务架构在中小型电商场景的落地实践
- **核心目标**：
  - 实现完整的租赁业务闭环（发布→下单→履约→归还→评价）
  - 采用微服务架构，保证系统的可扩展性和可维护性
  - 解决分布式环境下的数据一致性与高并发问题

## 二、设计概要（3-4页）

### 2.1 技术架构

```
┌─────────────────────────────────────────────────┐
│                   Vue 3 + Element Plus           │
├─────────────────────────────────────────────────┤
│              Spring Cloud Gateway (8080)         │
│         JWT认证 / 路由转发 / Sentinel限流         │
├──────┬──────┬──────────┬──────────┬─────────────┤
│用户服务│设备服务│  订单服务  │  优惠券服务 │  Common模块  │
│(8081) │(8082) │  (8083)  │  (8084)  │  (共享库)    │
├──────┴──────┴──────────┴──────────┴─────────────┤
│  Nacos(注册/配置) │ RabbitMQ │ Redis │ MinIO │ MySQL │
└─────────────────────────────────────────────────┘
```

- 前端：Vue 3 + Vite + Element Plus + Pinia + ECharts
- 后端：Java 17 + Spring Boot 3.2 + Spring Cloud Alibaba 2023
- 中间件：Nacos、RabbitMQ、Redis、MinIO、Sentinel、Druid
- 数据库：MySQL 8.x，15张业务表，7个唯一索引，15+复合索引

### 2.2 设计思路

- 按业务领域拆分为4个微服务（用户、设备、订单、优惠券）
- 同步调用走OpenFeign，异步事件走RabbitMQ
- 网关统一鉴权，下游服务通过Header获取用户身份
- 配置分层：Nacos共享配置 + 服务私有配置 + 敏感配置隔离

### 2.3 设计过程

1. 需求分析 → 功能模块划分 → 数据库ER设计
2. 搭建微服务脚手架 → 网关路由与鉴权
3. 逐模块实现业务逻辑 → 联调前端
4. 解决分布式一致性、并发安全等核心技术问题
5. 性能优化 → Docker Compose部署

## 三、自己所做的工作（重点，5-6页）

### 3.1 后端核心工作

| 模块 | 具体工作 |
|------|---------|
| **网关层** | 实现JwtAuthFilter统一鉴权、路由配置、Sentinel限流规则、CORS跨域处理、Knife4j文档聚合 |
| **用户服务** | 手机号注册登录、BCrypt密码加密、JWT双Token签发与刷新、用户资料管理、管理员用户管理 |
| **设备服务** | 设备CRUD、多条件搜索（关键词+品牌+价格区间）、MinIO图片上传（最多9张）、收藏功能、设备审核流程 |
| **订单服务** | 订单状态机（8个状态流转）、超时自动取消Job、评价系统、争议处理（5种类型+4种状态） |
| **优惠券服务** | 优惠券创建与发放、Redis原子扣减库存、领取/核销/退回、过期自动更新定时任务 |
| **公共模块** | 统一响应Result\<T\>、ErrorCode错误码体系、全局异常处理、AOP日志切面、防重复提交注解 |

### 3.2 分布式核心问题解决

- **可靠消息投递**：Outbox模式 — 同一事务写业务表+outbox表，定时任务轮询发布，指数退避重试（5s×2^n，上限300s，最多10次）
- **消息消费幂等**：mq_consume_log表 + UNIQUE(event_id, consumer)，DuplicateKeyException触发跳过
- **优惠券防超卖**：Redis DECR原子操作预扣库存，失败回滚Redis计数器
- **防重复提交**：@RepeatSubmit注解 + AOP + Redis SETNX，TTL过期自动释放

### 3.3 前端核心工作

- Vue 3 Composition API + `<script setup>` 全站开发
- Axios拦截器实现Token无感刷新 + 并发请求队列
- 管理后台Dashboard：ECharts订单趋势图、实时统计数据
- WebSocket + STOMP实现实时IM聊天
- Vite代码分割 + 路由懒加载优化首屏加载

### 3.4 数据库设计

- 15张表，设计7个唯一索引保证业务唯一性
- 15+复合索引针对高频查询优化
- 外键约束合理使用CASCADE/RESTRICT策略
- 逻辑删除（device表deleted字段）支持数据恢复

## 四、创新点与应用价值（重点，3-4页）

### 4.1 技术创新点

| 创新点 | 说明 | 解决的问题 |
|--------|------|-----------|
| **Outbox模式可靠消息** | 业务操作与消息发布在同一事务中写入outbox表，定时任务异步投递 | 避免"DB成功、MQ失败"导致的数据不一致，无需分布式事务 |
| **Redis原子库存扣减** | DECR原子操作 + 失败回滚机制 | 高并发场景下优惠券防超卖 |
| **网关统一鉴权链** | Gateway解析JWT注入Header，下游服务零JWT代码 | 职责分离，鉴权逻辑集中管理，降低服务间耦合 |
| **消费端幂等设计** | UNIQUE约束 + DuplicateKeyException兜底 | 消息重试场景下防止重复处理 |
| **AOP防重复提交** | 自定义注解 + Redis SETNX + TTL | 防止网络重试/双击导致的数据污染 |

### 4.2 应用价值

- **业务完整性**：覆盖租赁全生命周期，从设备发布到订单完结+评价+争议处理，形成完整业务闭环
- **架构可扩展**：微服务拆分使得各模块可独立开发、部署、扩容；新增业务域只需新增服务注册到Nacos
- **生产级安全**：JWT双Token无感刷新、Sentinel限流熔断、Druid SQL防火墙、敏感配置隔离
- **运维友好**：Docker Compose一键部署，Nacos配置热更新，Druid SQL监控，Sentinel Dashboard实时观测

### 4.3 应用效果

- 4个微服务 + 1个网关 + 6个中间件，完整跑通租赁全流程
- 15张数据库表，覆盖用户、设备、订单、优惠券、聊天、争议、消息队列基础设施等
- 前端包含用户端（首页/搜索/下单/聊天/个人中心）+ 管理后台（Dashboard/审核/用户/订单/优惠券/争议管理）

## 六、不足与进一步研究（1-2页）

### 6.1 当前不足

| 不足 | 说明 |
|------|------|
| **数据库未拆库** | 4个服务共用一个MySQL实例，未来需按服务拆分独立schema |
| **搜索能力有限** | 设备搜索使用MySQL LIKE，大数据量下性能差，未接入ES |
| **未接入真实支付** | 订单支付流程为模拟状态，未对接支付宝/微信支付 |
| **Sentinel限流较浅** | 仅在网关层配置，未深入到代码级热点参数限流 |
| **缺少CI/CD** | 无自动化构建部署流水线，依赖手动Docker Compose |

### 6.2 进一步研究方向

1. **Elasticsearch全文搜索**：替换LIKE查询，支持分词、拼音搜索、搜索建议
2. **数据库分库分表**：按服务拆分数据库，为后续数据量增长做准备
3. **Sentinel精细化流控**：@SentinelResource注解级限流 + 热点参数限流
4. **支付网关集成**：对接支付宝/微信支付SDK，实现真实交易流程
5. **Kubernetes容器编排**：K8s部署 + CI/CD流水线（GitHub Actions / Jenkins）
6. **争议通知MQ化**：将争议处理中的同步Feign调用改为MQ异步解耦
