# 功能模块详解

> 本文档详细描述各业务模块的功能设计、核心接口和数据流。

---

## 1. 用户模块（User Service — 8081）

### 1.1 注册与登录

**注册流程：**

```
前端 Register.vue
  → POST /user/register { phone, password, nickname }
  → UserService.register()
    → 手机号唯一性校验
    → BCrypt 加密密码
    → 插入 user 表 (role=USER, status=ACTIVE)
  → 返回成功
```

**登录流程：**

```
前端 Login.vue
  → POST /user/login { phone, password }
  → UserService.login()
    → 查询用户 → BCrypt 比对密码
    → JwtService.generateToken(userId, {role})
  → 返回 { token, userId, nickname, role }
  → 前端 Pinia Store 存入 localStorage
```

**Token 刷新：**

- 前端 Axios 拦截器捕获 401 响应
- 自动调用 `POST /user/refresh-token` 获取新 Token
- 刷新期间的并发请求排队等待，刷新完成后自动重放
- 若刷新也失败，清空登录状态跳转登录页

### 1.2 站内消息

消息由**其他服务通过 Feign** 调用 `POST /message/send` 写入。

触发场景：

| 场景 | 接收者 | 消息类型 |
|------|--------|---------|
| 出租者发货 | 租用者 | ORDER_STATUS |
| 租用者申请归还 | 出租者 | ORDER_STATUS |
| 确认归还 + 退押金 | 租用者 | ORDER_STATUS |
| 设备审核通过/驳回 | 设备所有者 | DEVICE_AUDIT |

前端 MainLayout 中轮询 `GET /message/unread-count` 显示未读红点。

### 1.3 管理员功能

| 接口 | 功能 |
|------|------|
| `GET /user/admin/list` | 分页查询用户列表（支持手机号/昵称搜索） |
| `PUT /user/admin/{id}/disable` | 禁用用户 |
| `PUT /user/admin/{id}/enable` | 启用用户 |

通过 `@AdminOnly` 注解 + `AdminInterceptor` 拦截器实现权限控制，从请求头 `X-User-Role` 校验。

## 2. 设备模块（Device Service — 8082）

### 2.1 设备发布

```
前端 DevicePublish.vue
  → 上传图片 POST /device/upload/images → 返回图片 URL 列表
  → POST /device/publish {
      userId, title, brand, model, description,
      imagePaths[], rentPrice, deposit, address
    }
  → DeviceService.publish()
    → 创建设备记录 (auditStatus=PENDING, status=OFFLINE)
  → 返回 { deviceId, auditStatus }
```

**字段校验规则：**

| 字段 | 规则 |
|------|------|
| title | 必填，≤128 字 |
| description | 必填，50-500 字 |
| imagePaths | 1-5 张图片 |
| rentPrice | > 0.01 |
| deposit | ≥ 0 |

### 2.2 设备搜索

```
GET /device/search?keyword=&brand=&minPrice=&maxPrice=&sortBy=&page=1&size=10
```

- **keyword**：模糊匹配 title 和 description
- **brand**：精确匹配品牌
- **minPrice / maxPrice**：价格区间
- **sortBy**：`price_asc` | `price_desc` | `time_desc`（默认时间倒序）
- 仅返回 `auditStatus=APPROVED` 且 `status=ACTIVE` 且 `deleted=0` 的设备

设备详情 `GET /device/{id}` 使用 **Redis 缓存**（TTL 30 分钟），更新/删除/上下架时清除缓存。

### 2.3 设备审核

管理员操作：

```
POST /device/audit { deviceId, auditStatus: "APPROVED" | "REJECTED" }
  → 更新 auditStatus
  → APPROVED → status 自动改为 ACTIVE
  → REJECTED → status 保持 OFFLINE
```

### 2.4 收藏夹

| 接口 | 说明 |
|------|------|
| `POST /favorite/add` | 添加收藏（上限 50 个） |
| `DELETE /favorite/remove` | 取消收藏 |
| `GET /favorite/check` | 检查是否已收藏 |
| `GET /favorite/list` | 获取收藏列表 |

### 2.5 图片上传

通过 MinIO 存储，支持单张和批量上传（最多 9 张）。

文件校验：

| 规则 | 限制 |
|------|------|
| 文件大小 | ≤ 5MB |
| 文件类型 | JPEG / JPG / PNG / WebP |
| 批量上传 | 最多 9 张 |

## 3. 订单模块（Order Service — 8083）

### 3.1 完整订单生命周期

```
PENDING_PAY → PAID → TO_SHIP → TO_RETURN → RETURNED → FINISHED
                                    ↘ OVERDUE ↗
PENDING_PAY → CANCELED（手动取消或 30 分钟超时自动取消）
```

### 3.2 创建订单

```
前端 OrderCreate.vue
  → POST /order/create { userId, deviceId, startTime, endTime, couponId? }
  → OrderService.createOrder()
    → [Feign] 调用 DeviceService 获取设备信息 → 校验设备状态
    → 计算租金 = rentPrice × 天数
    → [Feign] 调用 CouponService 获取优惠券 → 校验门槛 → 计算折扣
    → payAmount = totalRent - discountAmount
    → 创建订单记录 (status=PENDING_PAY)
  → 返回 { orderNo, totalRent, discountAmount, payAmount }
```

### 3.3 订单操作

| 操作 | 执行者 | 前置状态 | 后置状态 | 副作用 |
|------|--------|---------|---------|--------|
| 支付 | 租用者 | PENDING_PAY | PAID | 押金状态改为 PAID |
| 发货 | 出租者 | PAID | TO_SHIP | 站内信通知租用者 |
| 确认收货 | 租用者 | TO_SHIP | TO_RETURN | 站内信通知出租者 |
| 申请归还 | 租用者 | TO_RETURN | RETURNED / OVERDUE | 站内信通知出租者 |
| 确认归还 | 出租者 | RETURNED / OVERDUE | FINISHED | 退押金 + 站内信通知租用者 |
| 取消 | 租用者 | PENDING_PAY | CANCELED | — |

### 3.4 超时自动取消

`OrderTimeoutJob` 定时任务：

- 执行频率：每 60 秒
- 逻辑：查找 `status=PENDING_PAY` 且 `created_at < 当前时间-30分钟` 的订单
- 操作：批量 UPDATE 为 `CANCELED`（避免逐条查询的 N+1 问题）

### 3.5 评价系统

**创建评价条件：**

1. 订单状态为 `FINISHED`
2. 当前用户未对该订单评价过

**评价字段：**

| 字段 | 说明 |
|------|------|
| score | 评分（1-5） |
| content | 文字内容 |
| imagePaths | 评价图片（可选） |
| evaluatorId | 评价者 |
| evaluatedId | 被评价者 |
| deviceId | 关联设备 |

## 4. 优惠券模块（Coupon Service — 8084）

### 4.1 优惠券类型

| 类型 | 字段 | 说明 |
|------|------|------|
| `NO_THRESHOLD` | denomination | 无门槛，直接减免 |
| `THRESHOLD` | denomination + threshold | 满 threshold 减 denomination |

### 4.2 领取流程（防超发）

```
POST /coupon/receive { userId, couponId }
  → CouponService.receive()
    → Redis DECR 原子扣减库存
      → 库存 < 0 → 回补 + 抛出"已抢完"异常
    → 检查是否已领取（user+coupon 唯一键）
      → 已领取 → 回补 Redis + 抛出"已领取"异常
    → 查询优惠券信息 → 校验状态
    → 创建 user_coupon 记录（expire_time = now + valid_days）
    → 更新 coupon.used_count
```

关键点：**先扣 Redis 库存**（原子操作，防止并发超发），再做数据库操作，失败则回补库存。

### 4.3 优惠券状态流转

```
DRAFT → PUBLISHED → EXPIRED / OFFLINE
```

- `PUBLISHED`：用户可领取
- `EXPIRED`：过期不可用
- `OFFLINE`：管理员手动下架

## 5. 管理后台

### 5.1 数据看板

| 统计项 | 数据来源 |
|--------|---------|
| 注册用户数 | `GET /user/stats/count` |
| 设备总数 | `GET /device/stats/count` |
| 待审核数 | `GET /device/stats/pending` |
| 订单总数 | `GET /order/stats/count` |

### 5.2 访问控制

1. **前端路由守卫**：`meta.requireAdmin` → 非 ADMIN 角色重定向到首页
2. **后端 @AdminOnly 注解**：`AdminInterceptor` 拦截器检查 `X-User-Role` 请求头
3. **网关 JWT 鉴权**：`JwtAuthFilter` 从 Token 解析 role 写入 `X-User-Role` 请求头
