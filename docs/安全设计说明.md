# 安全设计说明

> 本文档描述平台的认证鉴权、权限控制、数据安全和防护措施。

---

## 1. 认证体系（JWT）

### 1.1 Token 签发

| 配置项 | 值 | 说明 |
|--------|-----|------|
| 签名算法 | HMAC-SHA256 | 对称加密 |
| 密钥长度 | ≥ 256 bit（32 字符） | 满足 HMAC-SHA256 安全要求 |
| 有效期 | 120 分钟 | 可通过 Nacos 热更新 |
| 签发者 | `camera-rental` | iss 字段 |

**Token Payload：**

```json
{
  "sub": "userId",
  "role": "USER | ADMIN",
  "iss": "camera-rental",
  "iat": 1709510400,
  "exp": 1709517600
}
```

### 1.2 Token 传递链路

```
前端 → [Authorization: Bearer <token>]
  → Gateway JwtAuthFilter
    → 解析 Token，提取 sub (userId) 和 role
    → 写入请求头 X-User-Id / X-User-Role
    → 转发到下游服务
  → 下游服务
    → 从请求头读取 X-User-Id / X-User-Role
    → 用于业务逻辑（如验证操作权限）
```

**要点：** 下游服务**不直接解析 JWT**，只信任网关注入的请求头。简化了服务间的认证逻辑。

### 1.3 Token 刷新机制

```
前端 Axios 响应拦截器
  → 收到 401 响应
  → 检查是否正在刷新
    → 是：将请求加入等待队列
    → 否：标记为"正在刷新"
  → POST /user/refresh-token (旧 Token)
    → 成功：存储新 Token → 重放等待队列中的请求
    → 失败：清空登录状态 → 跳转登录页
```

### 1.4 密钥管理

JWT 密钥存储在 Nacos `cipher-config.yaml`（`SHARED_GROUP`），通过环境变量 `${JWT_SECRET}` 引用。

- `cipher-config.yaml` **不入 Git**（在 `.gitignore` 中排除）
- 仓库只提供 `cipher-config.yaml.example` 模板
- 建议使用 `openssl rand -base64 32` 生成密钥

## 2. 权限控制

### 2.1 三层权限体系

| 层 | 实现 | 说明 |
|----|------|------|
| **网关层** | `JwtAuthFilter` | 最小公开接口放行，其余需要有效 Token；管理面仅内网/IP 白名单 |
| **服务层** | `@AdminOnly` + `AdminInterceptor` | 管理员接口权限校验 |
| **前端层** | 路由守卫 `meta.requireAuth` / `meta.requireAdmin` | 未登录/非管理员重定向 |

### 2.2 网关白名单

**公开接口（免鉴权）：**

| 路径 | 方法 | 说明 |
|------|------|------|
| `/user/register` | POST | 注册 |
| `/user/login` | POST | 登录 |
| `/user/refresh-token` | POST | 刷新 AccessToken |
| `/device/search` | GET | 设备搜索 |
| `/device/{id}` | GET | 设备详情（仅数字 ID） |
| `/actuator/health` | GET | 健康检查 |

**管理面访问控制（不对公网开放）：**

| 路径模式 | 访问策略 |
|---------|----------|
| `/doc.html`、`/swagger-ui/**`、`/v3/api-docs/**`、`/knife4j/**` | 仅内网/IP 白名单 |
| `/**/druid/**` | 仅内网/IP 白名单 + 默认关闭（临时开窗） |
| `/actuator/info`、`/actuator/metrics`、`/admin/**` | 仅内网/IP 白名单 |

**Token 过期响应约定：**

```json
{"code":2005,"message":"TOKEN_EXPIRED","data":null}
```

### 2.3 管理员权限拦截

```java
@AdminOnly  // 标注在 Controller 方法上
public Result<?> adminOperation() { ... }
```

`AdminInterceptor` 工作流程：

1. 检查方法是否标注 `@AdminOnly`
2. 读取请求头 `X-User-Role`
3. 非 `ADMIN` → 抛出 403 BusinessException

### 2.4 用户身份验证

`UserController` 中操作个人数据的接口（如修改资料、修改密码）会校验：

```java
private void verifyIdentity(Long pathUserId, HttpServletRequest request) {
    String headerUserId = request.getHeader("X-User-Id");
    if (!String.valueOf(pathUserId).equals(headerUserId)) {
        throw new BusinessException(ErrorCode.FORBIDDEN, "无权操作");
    }
}
```

防止用户 A 修改用户 B 的资料。

## 3. 密码安全

### 3.1 BCrypt 加密

- 使用 `BCryptPasswordEncoder`（Spring Security Crypto）
- 自动加盐（salt 存在 hash 中），每次加密结果不同
- 暴力破解成本极高

### 3.2 密码规则

前端验证（`validate.js`）：

| 规则 | 要求 |
|------|------|
| 最小长度 | 6 位 |
| 复杂度 | 必须同时包含数字和字母 |

### 3.3 密码不暴露

- `User` 实体的 `password` 字段标注 `@JsonIgnore`，序列化时自动排除
- API 响应中**永远不包含**密码字段

## 4. 数据安全

### 4.1 敏感配置隔离

所有密码、密钥集中在 `cipher-config.yaml`：

| 配置 | 说明 |
|------|------|
| `DATASOURCE_PASSWORD` | 数据库密码 |
| `JWT_SECRET` | JWT 签名密钥 |
| `REDIS_PASSWORD` | Redis 密码 |
| `MINIO_ACCESS_KEY` / `MINIO_SECRET_KEY` | MinIO 凭证 |
| `DRUID_PASSWORD` | Druid 监控密码 |

**安全措施：**

- `.gitignore` 排除 `cipher-config.yaml`
- 仅提供 `.example` 模板文件
- Nacos 配置中心存储，不落地到本地文件

### 4.2 SQL 注入防护

**多层防护：**

| 层 | 措施 |
|----|------|
| ORM | MyBatis-Plus 使用参数化查询（`#{}` 占位符） |
| 连接池 | Druid `wall` 过滤器（SQL 防火墙） |
| 应用层 | 输入参数校验（Jakarta Validation） |

### 4.3 请求参数校验

使用 Jakarta Bean Validation（`@Valid` + 注解）：

```java
@NotBlank(message = "标题不能为空")
@Size(max = 128)
private String title;

@DecimalMin(value = "0.01")
private BigDecimal rentPrice;
```

全局异常处理器捕获 `MethodArgumentNotValidException`，返回友好的字段级错误信息。

### 4.4 XSS 防护

- 前端使用 Vue 模板语法（自动转义 HTML）
- 后端 JSON 序列化不输出原始 HTML
- 文件上传限制文件类型（仅 JPEG / PNG / WebP）

## 5. 接口防护

### 5.1 防重复提交

`@RepeatSubmit` 注解基于 Redis 分布式锁：

```java
@RepeatSubmit(interval = 3, message = "请勿重复提交")
@PostMapping("/create")
public Result<?> createOrder(...) { ... }
```

- 默认间隔 3 秒
- Key 由 `URI + 参数哈希 + Token` 构成
- Redis `SETNX` 保证原子性

### 5.2 Sentinel 限流

网关层配置 Sentinel：

- 路由级别限流（防止单个服务被打爆）
- 降级响应：`{"code":503,"message":"服务繁忙，请稍后再试"}`
- Feign 调用配合 Sentinel 触发 Fallback 降级

### 5.3 优惠券防超发

```
Redis DECR (原子操作)
  → remaining < 0 → Redis INCR 回补 → 拒绝
  → remaining ≥ 0 → 数据库校验 → 成功/失败（失败则回补）
```

**先 Redis 后 DB**，利用 Redis 原子操作解决高并发下的超卖问题。

### 5.4 文件上传安全

| 检查项 | 限制 |
|--------|------|
| 文件大小 | ≤ 5MB |
| Content-Type | 白名单（image/jpeg, image/png, image/webp） |
| 文件数量 | 单次最多 9 张 |
| 文件名 | 服务端重新生成 UUID 文件名，不使用原始文件名 |

## 6. CORS 安全

网关统一配置 CORS：

```yaml
allowed-origins: ["http://localhost:3000"]  # 仅允许前端域名
allow-credentials: true                      # 允许携带 Cookie/Token
max-age: 3600                                # 预检缓存 1 小时
```

**生产环境注意：** 应将 `allowed-origins` 改为实际的前端部署域名，不要使用 `*`。

## 7. 日志安全

### 7.1 操作日志

所有关键业务操作通过 `@OperationLog` 注解记录：

- 操作类型和描述
- 请求 URL、方法、参数
- 响应结果
- 执行耗时
- User-Agent

### 7.2 日志脱敏

- 日志中不输出密码原文
- Token 解析失败只记录错误类型，不记录 Token 全文

### 7.3 日志文件管理

```yaml
logging.logback.rollingpolicy:
  max-file-size: 100MB
  max-history: 30
```

滚动策略：单文件最大 100MB，保留 30 天。
