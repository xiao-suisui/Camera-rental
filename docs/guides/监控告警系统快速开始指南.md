## 📋 第一步：集成Spring Boot Actuator

### 1. 在父POM中添加依赖管理

打开 `service/pom.xml`，在 `<dependencyManagement>` 中添加:

```xml
<!-- Spring Boot Actuator -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-actuator</artifactId>
    <version>${spring-boot.version}</version>
</dependency>

<!-- Micrometer Prometheus -->
<dependency>
    <groupId>io.micrometer</groupId>
    <artifactId>micrometer-registry-prometheus</artifactId>
    <version>1.12.4</version>
</dependency>
```

### 2. 在各个微服务中添加依赖

在每个服务的 `pom.xml` 中添加:

```xml
<!-- Actuator -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-actuator</artifactId>
</dependency>

<!-- Prometheus -->
<dependency>
    <groupId>io.micrometer</groupId>
    <artifactId>micrometer-registry-prometheus</artifactId>
</dependency>
```

### 3. 配置Actuator端点

在每个服务的 `application.yml` 中添加:

```yaml
management:
  endpoints:
    web:
      exposure:
        include: '*'  # 暴露所有端点（生产环境建议指定具体端点）
      base-path: /actuator
  endpoint:
    health:
      show-details: always
    metrics:
      enabled: true
    prometheus:
      enabled: true
  metrics:
    tags:
      application: ${spring.application.name}
    export:
      prometheus:
        enabled: true
  health:
    defaults:
      enabled: true
```

### 4. 验证Actuator

启动服务后访问：
- 健康检查: `http://localhost:8081/actuator/health`
- 所有端点: `http://localhost:8081/actuator`
- Prometheus指标: `http://localhost:8081/actuator/prometheus`

## 🐳 第二步：部署Prometheus

### 1. 创建Prometheus配置文件

创建 `service/monitoring/prometheus.yml`:

```yaml
global:
  scrape_interval: 15s # 采集间隔
  evaluation_interval: 15s # 规则评估间隔

# 告警管理器配置（可选）
alerting:
  alertmanagers:
    - static_configs:
        - targets: []

# 采集配置
scrape_configs:
  # Prometheus自身监控
  - job_name: 'prometheus'
    static_configs:
      - targets: ['localhost:9090']

  # Gateway服务
  - job_name: 'gateway'
    metrics_path: '/actuator/prometheus'
    static_configs:
      - targets: ['host.docker.internal:8080']
        labels:
          service: 'gateway'

  # User服务
  - job_name: 'user-service'
    metrics_path: '/actuator/prometheus'
    static_configs:
      - targets: ['host.docker.internal:8081']
        labels:
          service: 'user-service'

  # Device服务
  - job_name: 'device-service'
    metrics_path: '/actuator/prometheus'
    static_configs:
      - targets: ['host.docker.internal:8082']
        labels:
          service: 'device-service'

  # Order服务
  - job_name: 'order-service'
    metrics_path: '/actuator/prometheus'
    static_configs:
      - targets: ['host.docker.internal:8083']
        labels:
          service: 'order-service'

  # Coupon服务
  - job_name: 'coupon-service'
    metrics_path: '/actuator/prometheus'
    static_configs:
      - targets: ['host.docker.internal:8084']
        labels:
          service: 'coupon-service'
```

### 2. 使用Docker启动Prometheus

```bash
# Windows PowerShell
docker run -d `
  --name prometheus `
  -p 9090:9090 `
  -v ${PWD}/service/monitoring/prometheus.yml:/etc/prometheus/prometheus.yml `
  prom/prometheus

# Linux/Mac
docker run -d \
  --name prometheus \
  -p 9090:9090 \
  -v $(pwd)/service/monitoring/prometheus.yml:/etc/prometheus/prometheus.yml \
  prom/prometheus
```

### 3. 访问Prometheus

打开浏览器访问: `http://localhost:9090`

验证指标采集：
- 进入 Status -> Targets 查看所有服务状态
- 进入 Graph 页面，输入查询: `up` 查看所有服务状态

## 📈 第三步：部署Grafana

### 1. 使用Docker启动Grafana

```bash
docker run -d `
  --name grafana `
  -p 3000:3000 `
  grafana/grafana
```

### 2. 登录Grafana

- 访问: `http://localhost:3000`
- 默认用户名: `admin`
- 默认密码: `admin`
- 首次登录会要求修改密码

### 3. 添加Prometheus数据源

1. 登录后，点击左侧菜单 ⚙️ Configuration -> Data Sources
2. 点击 "Add data source"
3. 选择 "Prometheus"
4. 配置:
   - Name: `Prometheus`
   - URL: `http://host.docker.internal:9090` (Windows/Mac) 或 `http://localhost:9090` (Linux)
5. 点击 "Save & Test"，确认连接成功

### 4. 导入Spring Boot仪表板

1. 点击左侧菜单 ➕ -> Import
2. 输入仪表板ID: `11378` (JVM Micrometer)
3. 点击 "Load"
4. 选择刚才创建的Prometheus数据源
5. 点击 "Import"

推荐的仪表板ID:
- `11378` - JVM (Micrometer)
- `12900` - Spring Boot Statistics
- `4701` - JVM Dashboard

## 🔔 第五步：配置告警规则

### 1. 创建告警规则文件

创建 `service/monitoring/alert-rules.yml`:

```yaml
groups:
  - name: camera_rental_alerts
    interval: 30s
    rules:
      # 服务不可用告警
      - alert: ServiceDown
        expr: up{job=~".*-service"} == 0
        for: 1m
        labels:
          severity: critical
        annotations:
          summary: "服务 {{ $labels.job }} 不可用"
          description: "{{ $labels.job }} 已经下线超过1分钟"

      # 高错误率告警
      - alert: HighErrorRate
        expr: |
          sum(rate(http_server_requests_seconds_count{status=~"5.."}[5m])) by (service) / 
          sum(rate(http_server_requests_seconds_count[5m])) by (service) > 0.05
        for: 2m
        labels:
          severity: warning
        annotations:
          summary: "{{ $labels.service }} 错误率过高"
          description: "{{ $labels.service }} 5分钟内错误率超过5%"

      # 响应时间过长告警
      - alert: HighResponseTime
        expr: |
          histogram_quantile(0.99, 
            sum(rate(http_server_requests_seconds_bucket[5m])) by (le, service)
          ) > 3
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "{{ $labels.service }} 响应时间过长"
          description: "{{ $labels.service }} P99响应时间超过3秒"

      # 内存使用率过高告警
      - alert: HighMemoryUsage
        expr: |
          sum(jvm_memory_used_bytes{area="heap"}) by (service) / 
          sum(jvm_memory_max_bytes{area="heap"}) by (service) > 0.85
        for: 3m
        labels:
          severity: warning
        annotations:
          summary: "{{ $labels.service }} 内存使用率过高"
          description: "{{ $labels.service }} 堆内存使用率超过85%"

      # GC频率过高告警
      - alert: FrequentGC
        expr: rate(jvm_gc_pause_seconds_count[1m]) > 10
        for: 2m
        labels:
          severity: warning
        annotations:
          summary: "{{ $labels.service }} GC频率过高"
          description: "{{ $labels.service }} 每分钟GC超过10次"

      # 数据库连接池耗尽告警
      - alert: DatabaseConnectionPoolExhausted
        expr: hikaricp_connections_active >= hikaricp_connections_max * 0.9
        for: 1m
        labels:
          severity: critical
        annotations:
          summary: "数据库连接池即将耗尽"
          description: "连接池使用率超过90%"
```

### 2. 更新Prometheus配置

修改 `prometheus.yml`，添加告警规则:

```yaml
rule_files:
  - "alert-rules.yml"
```

### 3. 重启Prometheus

```bash
docker restart prometheus
```

## 🎯 第七步：自定义业务指标

### 1. 在代码中添加自定义指标

```java
@Service
public class MetricsService {
    
    private final MeterRegistry meterRegistry;
    
    public MetricsService(MeterRegistry meterRegistry) {
        this.meterRegistry = meterRegistry;
    }
    
    // 订单创建计数器
    public void recordOrderCreated(String deviceType) {
        Counter.builder("order.created")
                .tag("device_type", deviceType)
                .description("订单创建数量")
                .register(meterRegistry)
                .increment();
    }
    
    // 优惠券领取计数器
    public void recordCouponClaimed(Long couponId) {
        Counter.builder("coupon.claimed")
                .tag("coupon_id", String.valueOf(couponId))
                .description("优惠券领取数量")
                .register(meterRegistry)
                .increment();
    }
    
    // 设备浏览量
    public void recordDeviceView(Long deviceId) {
        Counter.builder("device.view")
                .tag("device_id", String.valueOf(deviceId))
                .description("设备浏览量")
                .register(meterRegistry)
                .increment();
    }
    
    // 支付金额
    public void recordPayment(Double amount) {
        DistributionSummary.builder("payment.amount")
                .description("支付金额分布")
                .baseUnit("CNY")
                .register(meterRegistry)
                .record(amount);
    }
    
    // 订单处理时间
    public void recordOrderProcessingTime(long milliseconds) {
        Timer.builder("order.processing.time")
                .description("订单处理时间")
                .register(meterRegistry)
                .record(milliseconds, TimeUnit.MILLISECONDS);
    }
}
```

### 2. 在Service中使用

```java
@Service
public class OrderService {
    
    private final MetricsService metricsService;
    
    public OrderCreateResponse createOrder(OrderCreateRequest request) {
        long startTime = System.currentTimeMillis();
        
        try {
            // 创建订单逻辑
            Order order = doCreateOrder(request);
            
            // 记录指标
            metricsService.recordOrderCreated(order.getDeviceType());
            metricsService.recordPayment(order.getTotalAmount());
            
            return buildResponse(order);
        } finally {
            long duration = System.currentTimeMillis() - startTime;
            metricsService.recordOrderProcessingTime(duration);
        }
    }
}
```

### 3. 在Grafana中查询

```promql

# 按设备类型统计订单
```

## 📝 监控最佳实践

### 1. 指标命名规范
```
{namespace}_{subsystem}_{metric_name}_{unit}

# 示例:
camera_rental_order_created_total
camera_rental_payment_amount_cny
```

### 2. 合理设置告警阈值
- 错误率: > 5%
- 响应时间P99: > 3秒
- 内存使用率: > 85%
- GC频率: > 10次/分钟

### 3. 告警分级
- **Critical**: 立即处理（服务宕机、数据库连接失败）
- **Warning**: 关注处理（性能下降、错误率上升）
- **Info**: 信息通知（部署通知、配置变更）

### 4. 避免告警疲劳
- 设置合理的告警阈值
- 避免重复告警
- 设置告警恢复通知
